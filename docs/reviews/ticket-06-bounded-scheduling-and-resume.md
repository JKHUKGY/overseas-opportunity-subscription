## Spec

首轮发现 2 项问题，无额外范围扩张：

1. 旧执行器等待期间停止旧计划并创建新计划后，旧执行器可能直接执行新计划。违反启动／停止控制的预期，以及 start 只保存计划的明确行为。已修正为绑定执行器初始计划 ID，在事务内认领前再次验证；计划变化返回 schedule_changed，不执行新计划。
2. 限流推迟先覆盖 next_run_at，可能丢失此前已发生的观察缺口。违反“恢复后保留实际执行时间与缺口”。已调整为先记录迟到缺口，再推迟到来源允许时间；后续准时执行不重复记录该缺口。

两项均通过公开操作、可控时间和真实 SQLite 先复现失败，再修复通过。Spec 评审者复核确认原发现全部修复，并独立复跑 16 项调度专项测试通过，未发现遗留问题。

## 实施边界

调度运行于 macOS／Linux 的本机本地存储，显式 schedule work 是前台执行器，schedule start/resume 仅改变计划。暂停或停止不强制打断当前轮次。认领后发生中断仍消耗一次预算，避免重启绕过上限；重叠和来源等待不消耗次数。

普通未结束采集报告保留 running 和缺少结束记录的历史事实，调度 interrupted_run 事件标记恢复判断。schedule 命令退出码 0 表示控制／触发被处理，来源结果以 last_result 和对应运行报告为准。每日和观察期汇总属于第 07 张。
