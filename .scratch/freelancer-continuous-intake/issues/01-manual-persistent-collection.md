# 01: 手动采集并持久保存候选

**What to build:** 项目运营者能够手动完成一次有界 Freelancer 采集，查看持久保存的候选及本轮基础结果；重复执行或重启后仍能正确识别同一项目。建立可工作的第一条完整路径，保持历史原型与实验记录原样。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

Execution: in-progress

- [ ] 提供一次完整采集运行入口；可传入查询配置、来源访问能力、时间和持久保存能力。没有定时配置时只执行一次，不启动后台循环。
- [ ] 从 Freelancer 正常只读搜索取得项目；初始查询沿用 illustration、portrait，每组最多五条、每组一页，可配置。设置并遵守明确的请求和超时上限，实际范围记入报告。
- [ ] 按来源及稳定项目 ID 保存唯一候选，保留原网址、规范化网址、标题、必要正文、来源时间、首次发现与最近读取时间、原币种预算和计价单位、原始状态及待整理状态；未知值不编造。
- [ ] 同轮跨查询重叠、重复运行及应用重启后重复读取不产生候选副本，不改写首次发现时间。状态保存损坏时明确报错，不静默重建为空库。
- [ ] 运营者能查看当前保存候选及基础运行报告；报告包含范围、开始／结束、请求成功／失败、取得条目、唯一项目及新增／重复数量，且不将候选称为有效约稿机会。
- [ ] 凭证仅由外部配置注入，不出现在命令行明文、候选、报告或导出中；不保存需求方账户资料。
- [ ] 长期状态使用持久位置；实现独立于既有原型，不覆盖原型快照、历史标注或模拟状态。单次写入失败后数据可恢复且不会重复入库。
- [ ] 通过完整运行入口，以可控来源和真实隔离存储验证首次写入、查询重叠、重跑与重启后的去重、状态损坏及基础报告；自动化验收不依赖真实来源或账号。
- [ ] 不接入模型、不生成真实邮件、不投标、不联系需求方、不公开发布来源内容。后续更完整的错误恢复、字段变化、结束记录与调度分别由对应工单交付。
