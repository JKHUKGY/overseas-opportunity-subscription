# 05: 按来源删除要求清理关联数据

**What to build:** 项目运营者收到来源平台或原作者的明确删除要求后，能够显式清除相关候选详情、缓存、结束记录网址及关联索引，且不会误删其他项目或把普通结束当作相同操作。

**Blocked by:** 04 — 复查接单状态并排除确认结束的机会。

**Status:** ready-for-agent

Execution: complete

- [x] 提供显式来源删除操作，能够指定来源及相关项目身份／网址；无需自动联系平台或推断哪些作者要求过删除。
- [x] 活跃候选和已经形成普通结束记录的项目均可清理；覆盖应用维护的详情、导出缓存、结束记录中的网址及关联去重／复查索引。
- [x] 普通需求结束继续保留最小结束记录，来源删除按既有例外清除；不以来源删除替代普通结束或自动清空全部存档。
- [x] 删除完成结果可核查；重复请求可安全执行，过程失败时明确报告未完成并可恢复，不在删除后遗留含机会详情的诊断副本。
- [x] 不影响不同项目或身份相关参数不同的网址；清理全部身份记录后接受再次发现无法被原记录排除，不新增未经决定的永久屏蔽名单。
- [x] 通过公开来源删除入口验证清理与隔离，再从完整采集运行入口验证普通结束仍排除、显式删除后无法靠原记录排除、重复删除和中断恢复；以持久结果与后续运行行为验收。
