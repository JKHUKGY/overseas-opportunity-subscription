# 04: 复查接单状态并排除确认结束的机会

**What to build:** 项目运营者能够在持续采集时复查已存候选，保留无法核实的记录；确认结束后先持久写入最小结束记录再删除详情，并在中断或再次发现同一网址时继续正确排除。

**Blocked by:** 02 — 请求受限或失败时保全采集结果；03 — 重复采集识别内容变化与近期候选。

**Status:** ready-for-agent

Execution: complete

- [x] 完整运行在写入候选前检查独立结束记录；命中原网址或不改变身份的已知追踪参数变体时，不重新入库、整理或发起多余详情请求，不误排不同项目。
- [x] 对已存候选实行有界、可恢复的详情轮转复查；即使本轮搜索不再返回该项目也会被检查。与搜索共用总请求／时间预算，持久保存复查进度，避免固定候选长期饿死。
- [x] 详情读取使用已建立的字段和内容变化语义；成功复查更新核验时间，内容变化使旧整理结果失效，失败不伪造成功核验时间。
- [x] active/open 仅为当次观察；404、读取失败、大量申请、正在挑选、消失于搜索或超出三天窗口均不自动判定结束。含糊状态标注无法核实并保留候选。
- [x] 来源明确关闭或需求方明确已找到承接者等可靠证据才触发结束；Closed 不改写成已成交。来源状态映射有证据及测试，未知枚举保持未知。
- [x] 先持久写入独立结束记录，再删除详情。结束记录仅保留原帖网址、来源标识、删除时间、删除原因，不保留标题、正文、摘要、预算或需求方资料。
- [x] 结束记录写入失败保留详情；成功写入后、删除前中断，下一轮先排除该项目并补完删除，不能再次暴露或整理。普通结束记录长期保留且重复处理不重复创建。
- [x] 应用维护的详情副本和导出缓存同步清理，日志与历史报告不保留机会详情；运行结果区分复查成功／失败、确认结束、结束记录命中和待复查数量。
- [x] 从完整运行入口验证搜索消失后仍复查、预算受限下跨轮轮转、未知／失败状态保留、真实关闭、同网址及参数变体再发现、写入失败、写入后中断及重启恢复；使用真实隔离持久存储与来源／存储边界故障注入。
