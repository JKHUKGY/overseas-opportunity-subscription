# 06: 按配置定时运行、暂停与恢复

**What to build:** 项目运营者能够选择有限观察期和频率，让相同采集入口按配置运行，随时暂停与恢复，并看清限流、重叠触发及停机造成的观察缺口。

**Blocked by:** 02 — 请求受限或失败时保全采集结果。

**Status:** ready-for-agent

Execution: in-progress

- [ ] 定时调度只调用既有完整运行入口；不复制搜索、保存、状态和结束业务逻辑，后续对入口的完善自动用于定时运行。
- [ ] 启用时必须提供有效运行频率、请求／耗时预算及观察终点或最大次数；缺少有效上限不启动。无定时参数默认只运行一次，绝不默认后台持续执行。
- [ ] 可启动、暂停、恢复、停止并查看最近结果、下一次计划及实验终点；进度持久保存，恢复后不重置已完成次数或绕过结束条件。
- [ ] 遵守来源限流给出的最早可继续时间；频率到点但仍在退避时推迟执行，并把原因记录为可查看的结果。
- [ ] 同一运行未结束时重叠触发只能跳过或排队，不并发修改状态；中断后能辨别遗留运行并恢复，不重复入库或把过期锁永久视为运行中。
- [ ] 停机期间不声称采集成功；恢复后保留实际执行时间与缺口，不伪造错过的运行结果或历史项目。无需部署云服务或保证全天在线。
- [ ] 通过可控时钟和真实隔离存储验证到点调用、暂停／恢复、最大次数／终点停止、限流推迟、重叠保护、遗留运行恢复和停机缺口；只断言公开执行结果和调度状态。
- [ ] 本工单仅交付可配置的运行能力和验证，不擅自选择用户的实际频率或启动多日任务，也不以真实等待数天作为自动化测试方式。
