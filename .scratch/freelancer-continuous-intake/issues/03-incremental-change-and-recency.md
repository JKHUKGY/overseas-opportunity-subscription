# 03: 重复采集识别内容变化与近期候选

**What to build:** 项目运营者在重复采集后能查看哪些项目新增、未变化或正文变化，使用真实原始发布时间判断近期候选，并保留可信的预算和地域信息，避免旧摘要、采集时间或投标均价造成误导。

**Blocked by:** 01 — 手动采集并持久保存候选。

**Status:** ready-for-agent

Execution: in-progress

- [ ] 相同项目及内容重跑时保留内容版本与首次发现时间；影响后续整理的正文等输入变化时更新版本，使旧分类及摘要失效并回到待整理，不保存为多份候选。
- [ ] 原始发布时间、首次发现时间、最近读取时间及最近成功状态核验时间分开保存；来源时间变更只采用可核查的新来源值，不自动重置成运行时间。
- [ ] 原始时间未知、无效或无法可靠解析时保持未知，不算进已验证的近期候选。内部使用带时区时间，最近三天按原始发布时间与运行时刻计算并明确边界。
- [ ] 原币种最低／最高预算、未知预算、固定总价与时薪分别保留；不拿投标均价补预算，不混合计价单位，不生成虚构人民币换算。
- [ ] 地域未说明保持地域未说明，不从来源面向国际用户推断接受中国画师；关键词命中只保留为待整理候选，不生成可推送机会或自动摘要。
- [ ] 在候选查看与运行报告中展示内容变化和时间／字段状态，新增、重复未变化、变化及近期候选计数的定义清楚，跨查询重复不重复计数。
- [ ] 通过完整运行入口及跨轮来源响应验证正文不变／变化、旧整理结果失效、原始时间修正、三天边界内外、缺失／无效时间、缺失预算、时薪／固定价及地域未说明；检查真实保存结果和报告。
- [ ] 自动化测试仅把可控的既有整理结果作为测试前置数据，不因此新增模型调用、人工录入运营流程或摘要产品功能。
